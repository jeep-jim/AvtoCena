# Кеш фотографий каталога АвтоЦена

## Назначение

Посетители сайта не загружают фотографии с сайтов-источников. Им отдаются копии из Yandex Object Storage через `/api/catalog/images/{imageId}` с `Cache-Control: public, max-age=31536000, immutable` и ETag.

## Как работает загрузка

1. Парсер нормализует и проверяет URL по разрешённому списку доменов и SSRF-защите.
2. SHA-256 нормализованного исходного URL определяет один из 4096 JSON-шардов `catalog/image-source-cache/v1/000.json` — `fff.json`.
3. Если в шарде уже записан живой `objectKey`, исходный сайт не запрашивается. Выполняется только HEAD объекта в нашем Object Storage.
4. При первом появлении URL фотография скачивается с ограничением размера, проверяется MIME, автоматически ориентируется по EXIF, уменьшается без обрезки максимум до 1600×1200 и сохраняется в WebP quality 78 как `catalog/images/{market}/{checksum}.webp`.
5. Одинаковое содержимое имеет одинаковый `objectKey`, поэтому физическая копия изображения не создаётся повторно.
6. Соответствие исходного URL и сохранённого объекта записывается в шард. Конфликты параллельных workflow обрабатываются через ETag/условную запись.

## Защита сайтов-источников

- не больше 3 одновременных загрузок фотографий с одного домена;
- не больше 180 стартов загрузки в минуту с одного домена;
- после HTTP 403 или 429 домен временно ставится на паузу с увеличивающимся интервалом до 5 минут;
- редиректы ограничены тремя и каждый новый URL повторно проходит SSRF-проверку;
- разрешены только JPEG, PNG и WebP размером не больше `CATALOG_IMAGE_MAX_BYTES`.

Настройки можно снизить без изменения кода:

- `CATALOG_IMAGE_HOST_CONCURRENCY` — 1–8, по умолчанию 3;
- `CATALOG_IMAGE_HOST_RPM` — 30–600, по умолчанию 180;
- `CATALOG_IMAGE_SOURCE_CACHE_SHARD_LIMIT` — 100–500, по умолчанию 450.
- `CATALOG_IMAGE_MAX_WIDTH` — максимальная ширина кешированной фотографии, по умолчанию 1600;
- `CATALOG_IMAGE_MAX_HEIGHT` — максимальная высота, по умолчанию 1200;
- `CATALOG_IMAGE_WEBP_QUALITY` — качество WebP 55–90, по умолчанию 78.

Ссылки на все кадры продолжают храниться в JSON объявления. Оптимизация меняет только физический объект кеша и не уменьшает количество фотографий в галерее. Если отдельный исходный файл повреждён и Sharp не может его декодировать, публикация не падает: сохраняется уже ограниченный по размеру оригинал.

## Ограничение занимаемого места

- максимум 4096 шардов;
- максимум 450 записей в каждом шарде;
- абсолютный предел — 1 843 200 соответствий URL, после чего старые записи внутри заполненного шарда вытесняются;
- это индекс с метаданными, а не дополнительные копии фотографий;
- контентная дедупликация не позволяет одному и тому же файлу занимать место несколько раз.

Workflow `Catalog Object Storage cleanup` запускается ежедневно. Он сохраняет изображения текущего публичного поколения, внутреннего поколения и двух последних поколений. Непривязанные изображения удаляются только после защитного периода не меньше трёх суток. Если запись URL указывает на уже удалённый объект, следующая попытка проверит отсутствие через HEAD, скачает фотографию заново и обновит запись.

Аварийный workflow дополнительно может удалить свежие, но уже непривязанные изображения. Он всегда сохраняет текущий публичный каталог, текущий внутренний candidate pool и все фотографии, на которые они ссылаются.

## Проверка после изменений

- тест `image source cache reuses the stored Object Storage image without downloading the origin twice` доказывает, что повторный вызов использует сохранённый объект;
- production build и TypeScript должны пройти;
- после merge проверяются `/`, `/api/health` и workflow очистки Object Storage.
