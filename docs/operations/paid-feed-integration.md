# Подключение платных автомобильных фидов

Практический регламент AvtoCena, проверен по main 09.10.2026. Первый работающий пример — Che168 через auto-api.com. Этот документ описывает выполненное подключение, ежедневную работу и следующие улучшения. История запусков остаётся в [roadmap.md](../../roadmap.md), подробности исходного CSV — в [che168-bulk-import.md](che168-bulk-import.md).

## Что уже работает по Китаю

- Первый полный файл `active_offer.csv`: 2 893 496 089 байт, разделитель `|`; его дата и начальный курсор 11989266 связаны конфигурацией `data/catalog/che168-snapshot-v1.json`. Исходный файл был доступен у поставщика два дня, поэтому сначала создан собственный закрытый архив.
- Потоковый разбор CSV, SQLite-копия инвентаря на диске, затем полное применение `/changes`. Полная запись применяется сразу; изменение цены обновляет известную запись; `/offer` запрашивается при недостатке данных. Повторное чтение всех страниц `/offers` для ежедневной синхронизации не используется; один запрос `/offers` остаётся проверкой доступа перед сбором.
- Сжатые части архива защищены размером, привязкой к снимку и SHA-256. Реплика и журнал восстановления лежат в Object Storage, независимо от временного GitHub runner и срока хранения Actions artifacts.
- Рабочий прогресс сохраняется после законченных страниц: при 1000 событиях, 8 MiB накопленных данных либо 60 секундах. Это не опубликованный курсор: окончательный checkpoint меняется только после успешной публикации.
- Неверные год/модель исключаются поштучно; ошибки идентичности, целостности и незавершённый поток остаются блокирующими. Нет выдуманных характеристик, дат и массы.
- Парсинг HTML Китая в штатном China worker отключён условием `matrix.market != 'china'`. Дополнительный Autohome New сейчас не собирается; ранее опубликованные предложения сохраняются по действующим правилам свежести. Платный Che168 не подтверждает актуальность отдельного Autohome New.
- Фото массово не скачиваются: `CATALOG_IMAGE_STORAGE_MODE=source_urls_only`. Веб-приложение выдаёт защищённые URL фото; сервер загружает их по запросу пользователя с ограничениями и кешем.

Подтверждённый результат первой публикации: [run 37939223522](https://github.com/jeep-jim/AvtoCena/actions/runs/37939223522), поколение `gen_1791555837022_9a2cec74`, опубликованный курсор 11991886. Китай: 139 999 предложений, из них 137 268 Che168 и 2 731 сохранённое Autohome New. Независимая проверка [37951698479](https://github.com/jeep-jim/AvtoCena/actions/runs/37951698479) успешна. Это контрольная точка 09.10, не обещание постоянного количества. Из 139 999 карточек 75 533 имели оценочный расчёт, 64 466 требовали данных; точных подтверждённых расчётов в этом аудите — 0. Массовый перевод описаний 37951698728 завершился cancelled: завершение всего перевода не подтверждено.

## Как происходит ежедневное обновление

Текущее расписание `.github/workflows/catalog-refresh-china.yml`: `11 18 * * *`, ежедневно в **18:11 UTC / 01:11 Красноярск**. Китай явно исключён из общего трёхдневного интервала остальных non-Japan рынков; `pausedMarkets` сейчас пуст. Время означает запуск, а не готовность нового каталога. GitHub допускает задержки расписания; длительная публикация или занятый общий lock дополнительно откладывают результат.

1. GitHub Actions проверяет наличие собственного архива и доступ к API. Завершённый архив повторно у поставщика не скачивает.
2. Восстанавливает SQLite-реплику, связанную с последним успешно опубликованным курсором.
3. Читает изменения после этого курсора до конца доступного потока: новые объявления, обновления цен/данных, явные снятия. Сетевая ошибка или 404 без события снятия не означает продажу.
4. Сохраняет новую реплику и формирует полный актуальный набор для издателя. Проверяет возраст, происхождение, качество данных и расчёты; сохраняет другие рынки.
5. Строит новое поколение каталога, проверяет его и переключает активную версию. До переключения сайт читает прежнюю версию.
6. После успешной публикации записывает checkpoint `catalog/intake-cursors/v1/china.json` с поколением, курсором и репликой. Отдельный workflow `catalog-che168-verify-publication.yml` сверяет активное поколение, число карточек, курсор/реплику и расчёты.

Обычный сбой до публикации сохраняет прежний опубликованный checkpoint и каталог; рабочий журнал позволяет продолжить обработку. Особый случай — переключение каталога прошло, а запись checkpoint или последующая проверка упала: сначала сверить фактическое поколение и отчёты, не объявлять всё неудачным и не запускать полный импорт автоматически. Именно старый summary первой публикации потребовал независимого подтверждения.

Ручной штатный запуск: `workflow_dispatch` у `Catalog refresh china`. Исторический `reuseRunId` в push-маркере не применяется к schedule/dispatch: marker читается только для события push. Не обнулять курсор, не править дату CSV и не переиспользовать старые recovery artifacts для нового снимка.

Обещание поставщика «ежедневно» не задаёт точного часа готовности данных. Пока оставляем один запуск в сутки. Для надёжного попадания в свежую выгрузку нужно получить у поставщика время завершения обновления, часовой пояс и срок доступности истории `/changes`; затем поставить запуск после готовности с запасом. Срок хранения исходного CSV два дня **не равен** известному сроку хранения изменений. Если обновление поставщика закончилось после нашего запуска, оно попадёт в следующий цикл; дополнительно учитываются задержка источника и длительность публикации. Несколько ежедневных циклов с изменившимся курсором ещё нужно подтвердить наблюдением: первая публикация не доказывает ежедневную устойчивость.

## Где выполняется работа и что оплачивается

| Часть | Сейчас | Следствие для расходов |
| --- | --- | --- |
| Сбор исходных объявлений Che168 | У поставщика | Вместо собственного HTML-парсера используется оплаченный фид/API |
| Загрузка изменений, нормализация, сборка каталога | GitHub Actions, `ubuntu-latest` | Отдельный постоянно работающий сервер-парсер Китая этому пути не нужен |
| Архив, реплики, журналы, опубликованные поколения | Yandex Object Storage | Остаются хранение, операции и соответствующий трафик |
| Сайт и защищённая выдача фото | Веб-приложение в Yandex | Остаются вычисления/трафик; фото поставщика не означают нулевых расходов сайта |
| Переводы и обогащение | Отдельные процессы | Оцениваются отдельно, не включаются автоматически в цену фида |

Репозиторий AvtoCena публичный, jobs используют стандартный `ubuntu-latest`. Согласно [GitHub Actions billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions), стандартные GitHub-hosted runners публичных репозиториев бесплатны. Это не обещание отсутствия любых расходов на storage/artifacts или услуги других поставщиков. Тариф аккаунта и фактический счёт Yandex здесь не проверялись. Снижение расходов на собственный парсинг не означает бесплатный каталог целиком.

## Что оптимизировать дальше

Приоритеты ниже — план, а не уже внедрённые возможности.

| Приоритет | Изменение | Что измерить и сохранить |
| --- | --- | --- |
| 1 | Уменьшить полную пересборку при небольшом `/changes`: обновлять затронутые карточки/части и индексы, переиспользовать неизменившиеся объекты | Время intake/publish/verify отдельно, число событий и затронутых карточек, PUT/GET/байты, память; переключение целостного поколения и проверка других рынков обязательны |
| 2 | Пропускать тяжёлую публикацию при отсутствии значимых изменений | Сравнивать не только курсор: учитывать возраст/свежесть, курсы валют, тарифы расчёта, переводы и версию нормализации; нулевые изменения источника сами по себе недостаточны |
| 3 | Завершить перевод и повторно обрабатывать только новый/изменившийся текст | Кеш по тексту, языку и версии обработки; измерить фактически непереведённые поля, не объявлять отменённый перевод завершённым |
| 4 | Ввести безопасную очистку старых реплик, журналов и архивов | Защитить активный checkpoint, рабочее восстановление, резерв для отката и исходный снимок; сначала отчёт объёма/dry-run, затем отдельная политика удаления |
| 5 | Свести ежедневный контроль в короткий отчёт | Последняя успешная публикация, задержка, старый/новый курсор, добавлено/изменено/снято, изоляции по причинам, расчёты, выборка главной/списка/карточки и фото |

Сейчас изменение источника инкрементальное, **публикация остаётся полной**. China publisher имеет timeout 360 минут, heap до 24 GiB и дополнительный swap; это предельные настройки, не измеренный расход RAM и не обещанная длительность. Текущий watchdog запускается каждые два часа на 43-й минуте и применяет recovery policy; он не заменяет успешную суточную публикацию. Не ускорять расписание, пока не измерены несколько обычных циклов и длительность записи каталога.

## Шаблон для следующего рынка

1. **Контракт поставщика.** Зафиксировать рынок/покрытие, право публикации текста и фото, полный снимок и соответствующий курсор, точность дат, часовой пояс, валюту/единицы, дневной график, ограничения API, срок истории изменений, правила удаления и восстановления при истёкшем курсоре. Новому фиду без `/changes` нужен отдельный алгоритм сверки полных снимков; отсутствие строки считать снятием только при доказанной полноте и согласованном контракте.
2. **Идентичность и адаптер.** Стабильный внешний ID + канонический источник/рынок, сохранение source URL и времени наблюдения, нормализация схемы, валюта/единицы без догадок, дедупликация с прежними источниками. Исторический ID Che168 `autohome_used_china_open` не переименовывать механически: это часть совместимости. Для нового источника определить собственное соответствие.
3. **Секреты и хранение.** Отдельный secret/API-конфигурация; не копировать ключ, личный endpoint или пароль в Git, логи и документ. Закрытый архив, проверка хешей, отдельные пути реплик/журналов/checkpoint для рынка. Не использовать китайский cursor для другого рынка.
4. **Первичная загрузка.** Сохранить снимок до истечения ссылки; разобрать потоком, собрать дисковую реплику, применить все изменения от согласованного курсора. Изолировать допустимые дефекты поштучно, блокировать ошибки идентичности/целостности и обрыв потока. Сохранить отчёт причин исключения.
5. **Правила AvtoCena.** Non-Japan — до шести календарных лет с точностью исходной даты; Japan — 2010+. Недостающие редактируемые характеристики не исключают валидное предложение. Для грузовиков/автобусов ограничение касается разрешённой полной массы >3500 кг. Нет лимита по цене/мощности/доле источника; Europe максимум 50 000, остальные рынки без количественного потолка. Цены продавца и оценочные расчёты не выдавать за подтверждённую стоимость доставки.
6. **Фото и русский интерфейс.** Проверить разрешённые домены существующего photo proxy, подпись в web runtime, главную, каталог и детальную карточку. Не сохранять прямые URL в компактной выдаче без последующей защиты при отдаче. Не расширять proxy произвольными хостами. Проверить перевод названий/параметров/описаний отдельно от доступности фото.
7. **Публикация.** Сохранить другие рынки, сформировать/проверить новое поколение, переключить его, затем commit курсора и реплики. Подтвердить активный API, статистику источников, цену и фото на выборке. Отдельно проверить сбой до публикации и после переключения до checkpoint.
8. **Автоматизация.** Собственный workflow/рынок/секреты/concurrency, один согласованный график после готовности фида, независимая проверка опубликованного состояния. Проверить, что общий интервал или pause не подавляет ежедневный запуск. Старый парсер отключить только после приёмки замены и решения по источникам, которых платный фид не покрывает.
9. **Приёмка повторного цикла.** На фиксированных примерах подтвердить добавление, обновление цены, явное снятие, повтор страницы без дублей, восстановление после обрыва и невозможность commit неполной публикации. Проверить профильные существующие тесты и реальный следующий ежедневный цикл; записать run/generation/cursor/count в roadmap.

## Донастройка после подключения фида, 10.10.2026

Подготовка общих расчётов на GitHub дополнена запуском после независимой успешной проверки Che168, публикаций остальных рынков и ежедневно в 00:11 UTC (07:11 Красноярск, после смены UTC-даты в ключе расчёта). После deploy с ошибкой последующего postcheck тоже проверяется фактически работающая версия: SHA берётся из production health, исходники калькулятора скачиваются именно этой версии. SHA документации или импортёра нельзя выдавать за версию веб-калькулятора.

Активный publication lock откладывает подготовку; смена поколения или релиза во время проверки не считается успехом. Используются прежний проверенный калькулятор и проверки на отдельных холодных процессах; разрешены только производные selectors/кеши. Исходные карточки, курсор поставщика и manifest этим заданием не меняются. Это подготовка существующего кеша после новых данных, не внедрение частичной публикации. Кеш по-прежнему инвалидируется по фактическим курсам/настройкам/возрасту и другим зависимостям; один ночной прогрев не отменяет последующие изменения в течение дня.

### Порядок перехода рынков

В `apps/web/lib/catalog/importer.ts` Encar (Корея), Dubizzle (ОАЭ), MyAuto/AutoPapa (Грузия) подключены через `withGithubYandexSourceBridge`. Поэтому их GitHub job может выполнять сбор внутри Yandex веб-контейнера. Это конкретные кандидаты на замену фидом; выключать их до приёмки соответствующей замены нельзя. Guazi также имеет такой адаптер, но штатный China worker уже идёт по платному Che168 и HTML intake не вызывает. Наличие старого адаптера не доказывает текущего расхода.

Для каждого следующего платного рынка: подтвердить покрытие и оплату/доступ; принять полный снимок и изменения; сверить карточки, цены и снятия; затем отключить прежний сбор именно покрытых источников и проверить отсутствие его вызовов. Не покупать второй фид только ради числа машин без проверки пересечения источников. Япония требует отдельного контракта по результатам торгов/листам и данным «в наличии».

### Экономическая цель владельца

Ориентир владельца: 3–4 основных фида суммарно около 50 000 ₽/месяц; прежний Yandex около 2 000–2 500 ₽/день. При условных 30 днях это 60 000–75 000 ₽/месяц. Новая полная сумма — **50 000 ₽ + оставшийся Yandex + прочие услуги**, а не 50 000 ₽ ровно. При неизменных остальных расходах остаток Yandex должен быть меньше 10 000–25 000 ₽/месяц, чтобы итог был ниже указанного прежнего диапазона. Это арифметический сценарий по оценке владельца, не подтверждённый тариф фидов или прогноз достигнутой экономии.

В предыдущем [аудите 5–8 октября](../changes/2026-10-09-cloud-cost-spike-audit.md) на 08.10 контейнеры дали 1919,91 ₽ из 2238,63 ₽ после скидки. Разделение этой суммы между сборщиками и посетителями не доказано. Для подтверждения эффекта сравнивать полные дни биллинга до/после, вызовы сборщиков, CPU/RAM, исходящий Object Storage, публикации и трафик сайта. 4 ГБ RAM и ресурсы сайта вслепую не сокращать.
