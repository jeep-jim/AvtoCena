# Che168: полный файл и изменения

Получен 09.10.2026: active_offer.csv, разделитель |, срок хранения у поставщика — два дня. Выгрузка и соответствующий ей курсор 11989266 закреплены в data/catalog/che168-snapshot-v1.json. Проверенный размер — 2 893 496 089 байт. Дату файла нельзя менять без нового согласованного курсора. Пароль берётся только из существующего GitHub Actions secret AUTO_API_CHE168_KEY; в документацию, URL и логи его не добавлять.

1. China worker первым делом сохраняет сжатые части CSV в закрытом Object Storage. Range, размер, ETag и SHA-256 проверяются. Незаконченная загрузка возобновляется по частям; готовая копия больше не требует доступа к файлу у поставщика.
2. CSV читается потоком, с обработкой кавычек, переносов строк, Unicode и JSON внутри колонок. Файл целиком в память не загружается. Однозначно старые годы отбрасываются до тяжёлой нормализации; точные ограничения возраста/массы остаются у публикации. Отсутствие технических параметров само по себе не исключает объявление.
3. Рабочая SQLite-копия хранит объявления на диске. Полные записи из /changes применяются напрямую, изменения цены — к соответствующей известной записи. /offer нужен только при недостатке данных. Между запросами выдерживается 200 мс, ниже предоставленного лимита 400/мин.
4. Только законченные страницы изменений попадают в защищённый журнал восстановления. Ошибка/404 без явного снятия не означает продажу. Повторный запуск восстанавливает журнал, не теряя уже обработанные страницы.
5. После полного чтения потока формируется актуальный состав активных записей. Дата исходной карточки сохраняется; отдельно записывается подтверждение активности полным потоком изменений. Удалённые и изолированные записи не возвращаются из старого каталога.
6. Новая рабочая копия сохраняется неизменяемыми сжатыми частями. Ссылка на неё и курсор становятся основными только после успешной публикации через существующие проверки расчётов, качества, возраста, хранения и регрессий. Ошибка оставляет действующий каталог и опубликованный курсор прежними.
7. Последующие плановые запуски China выполняются ежедневно по существующему cron 18:11 UTC. Они восстанавливают собственную копию и читают изменения от опубликованного курсора. Семидневного возврата к постраничному /offers в этом пути нет. Штатный HTML-сбор Autohome New сейчас отключён; ранее опубликованные записи сохраняются по правилам свежести, платный Che168 их актуальность не подтверждает.

Архивная копия и реплики закрыты и не являются публичным каталогом. Фотографии в каталоге остаются URL источника. Архив не удаляется автоматически после двух дней. Старые реплики и журналы пока сохраняются для восстановления; политику очистки нужно вводить отдельно с защитой действующей реплики и неопубликованного рабочего прогресса.

Запуск: push нового маркера .github/market-runs/china-refresh.json либо workflow_dispatch у catalog-refresh-china.yml. Не использовать старый recoverPaidSnapshot/reuseRunId для нового CSV. Повторный импорт того же файла при утрате курсора безопасно воспроизводит исходный снимок и изменения; менять курсор вручную нельзя.

Наличие архива, завершение импорта и публикация — разные стадии. Подтверждать результат по отчёту intake (completed, replica, cursor), отчёту публикации (published, generationId) и сохранённому курсору. Одного успешного скачивания недостаточно.
