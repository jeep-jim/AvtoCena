# Помощник команды Топ Авто

## Состояние подключения

Интерфейс, проверка ролей, история, поиск и протокол действий реализованы. Авторизация модели и запись в GitHub не настроены автоматически. Без отдельного разрешённого подключения `/api/crm/assistant` честно возвращает `connected: false`, отправка сообщений выключена. Реальные ответы модели и создание PR требуют проверки после подключения. Не объявлять функцию полностью запущенной по наличию панели.

В официальной документации на 13.10.2026 Sign in with ChatGPT поддерживает разрешённые запросы через подписку для open-source/локальных приложений и описывает self-hosted VM. Документация отдельно направляет remotely hosted apps на согласование; регистрация привязана к конкретному пользователю и выбранному workspace. Эти сведения не подтверждают право раздать личную подписку всем сотрудникам веб-сайта. Нельзя переносить браузерные cookies, чужую сессию расширения или токены из среды разработки на production.

- https://developers.openai.com/siwc/token-sharing-open-source
- https://developers.openai.com/siwc/token-sharing-open-source/self-hosted-vms
- https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference
- https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations

Нужно выбрать и авторизовать поддерживаемое подключение, которое разрешает доступ команде. Подмена подключения подписки платным API без отдельного решения владельца не допускается. Локальный OAuth, перенос учётных данных и обновление токенов в этом выпуске **не реализованы**. Серверный адаптер принимает уже авторизованное подключение Responses (в том числе согласованный шлюз, который управляет обновлением OAuth).

## Конфигурация сервера

Значения задаются только в защищённой среде приложения; не в браузере, чате, публичном репозитории или roadmap:

- `TEAM_ASSISTANT_RESPONSES_URL`: полный HTTPS URL разрешённого Responses endpoint. Для официального прямого маршрута — `https://api.openai.com/v1/responses`; не ChatGPT backend-api.
- `TEAM_ASSISTANT_ACCESS_TOKEN`: токен именно этого подключения. Обновлением короткоживущих токенов должен управлять выбранный коннектор/шлюз. Не хранить постоянную копию OAuth access token без механизма обновления.
- `TEAM_ASSISTANT_MODEL`: доступная подключённому аккаунту модель, выбранная из его актуального списка. Модель не зафиксирована на старом SHA или названии.
- `TEAM_ASSISTANT_WEB_SEARCH=1`: только если поиск поддерживается и разрешён этим подключением. По умолчанию выключен. Поиск в каталоге и доступных CRM-записях реализован независимо.
- `TEAM_ASSISTANT_GITHUB_TOKEN`: отдельный минимально необходимый доступ к `jeep-jim/AvtoCena` для создания веток и черновых pull request. Без него правки можно подготовить в переписке, но нельзя записать в репозиторий. Не использовать автоматически существующие ключи сборщиков/деплоя.
- `AUTH_SECRET`/`NEXTAUTH_SECRET`: существующий серверный ключ шифрования; сохранять при смене контейнера, иначе старые переписки не расшифруются.

Текущий REG-деплой наследует среду работающего контейнера. Этот выпуск не меняет серверную конфигурацию, сборщики, DNS и миграцию; сам по себе merge не добавляет соединение модели. Настройку нужно выполнить отдельно с подтверждённым способом авторизации, после чего проверить полный `response.completed`, а не HTTP200. Никакого автоматического платного fallback.

## Доступ и действия

- `/api/crm/assistant`: только активные owner/admin/manager компании `dealer_topavto` с правом `assistant`. Проверка актуального пользователя на каждом запросе. Внешние дилеры и гости не получают историю и панель.
- Переписка личная, зашифрована AES-GCM на сервере, до 40 сообщений; одна выполняемая операция на пользователя, 40 запросов/час. История другого сотрудника недоступна. Очистка удаляет текущую сохранённую историю; это не удаление старых версий хранилища.
- Контекст: видимый текст и разрешённые поля текущей страницы. Можно отключить перед отправкой. Пароли, скрытые поля и права не включаются; для других чувствительных блоков использовать `data-assistant-private`. Нельзя считать содержимое страницы инструкцией к расширению прав.
- Поиск: опубликованные автомобили/фото и доступные сотруднику клиенты/заявки. Не полный доступ ко всему хранилищу. Для внешних характеристик нужен разрешённый web search и проверяемый источник; неизвестные характеристики не подставлять как факт.
- Заполнение: только черновик открытой формы клиентов/заявок/каталога/расчётов при соответствующем существующем праве. Пользователь видит точные поля, подтверждает подстановку; ручные изменения не затираются. Кнопка сохранения формы не нажимается. После перезагрузки старые предложения требуют повторной подготовки.
- `assistantCode`: по умолчанию только владельцы, выдаёт только владелец в «Команда и права». Перед созданием правки требуется отдельная кодовая фраза (начальное значение задано владельцем, хранится только digest). Смена — в настройках помощника по текущей фразе, только владельцем. Фраза не передаётся модели.
- Код: только до трёх прочитанных файлов `.tsx/.css` интерфейса; backend/API/auth/права/сам помощник исключены. Полный diff виден человеку. Base SHA и старое содержимое перепроверяются. После подтверждения создаётся **draft PR**, main и production не меняются. Выполнение shell, автоматическое тестирование/слияние/деплой помощником не реализованы. При неопределённом результате записи операция блокируется от повтора, сначала проверить созданную ветку/PR.
- Изменения доступов, настройки фразы и передача действий фиксируются; тексты клиентов и кодовая фраза не включаются в журнал действий.

## Проверка

`node --import tsx --test tests/team-assistant.test.ts`

`node node_modules/typescript/bin/tsc --noEmit --incremental false -p apps/web/tsconfig.json`

`PLAYWRIGHT_MODULE=<playwright> CHROME_BIN=<chromium> node tests/browser/team-assistant.mjs`

Браузерный сценарий использует подставленные ответы API: это проверка настоящих компонентов, не доказательство живого подключения ChatGPT. После авторизации отдельно проверить реальный ответ, источник, пустой/оборванный поток, права менеджера и один согласованный draft PR без production-публикации.
