# AJ System: Китай и Корея

## Проверенный статус — 17.10.2026, Asia/Krasnoyarsk

Владелец сообщил о покупке обоих рынков и поручил подключить их, сохранив нынешний китайский фид до сравнения. Переданное ранее сообщение поставщика называет таблицы `china` и `korea`.

В CRM `/crm/site` включены отдельные `ajes_china_feed` и `ajes_korea_feed`; оба изменения подтверждены интерфейсом после сохранения. `che168_feed` остаётся включённым, китайский HTML-резерв выключен. Сейчас новые выключатели разрешают только проверку образца. Публичный импорт новых рынков НЕ реализован и НЕ включён. В интерфейсе это явно указано.

Один запуск «Проверить 5 автомобилей» для Китая вернул «Поставщик отклонил подключение». По установленному обработчику это `visitor_restricted`: короткий ответ поставщика вида `bot`/`botN`, не JSON-массив машин. Конкретный цифровой суффикс не сохранён и не установлен; называть его именно bot2 нельзя.

Фиксированный SQL: `select * from china limit 5`. Использован сохранённый общий доступ; endpoint `/gzip/` на ранее выданном адресе. Код передаёт `x-real-ip` запроса CRM, без подмены адреса. Фактическое значение IP в доступном интерфейсе не отображается и в этой проверке не извлечено. Секреты и URL с ключом в документы не записываются.

После отказа повторных запросов другим IP/путём не выполняли. Запрос `korea` не запускали после отказа общего поставщика; её доступность НЕ установлена. Отказ текущему подключению не доказывает, что оба оплаченных доступа отключены либо что ошибка находится только у поставщика.

## Что подтверждает документация

Источник: https://avto.jp/api?enter — прочитан17.10.2026. Документация перечисляет Китай и Корею, период обновления списков12часов; для Кореи описаны дополнительные history/inspection/ajax. Это не доказывает валюту, множитель цены, единицы мощности либо договорённость о полном импорте. Эти параметры нельзя переносить из японской таблицы stats.

## Продолжение после разрешения отказа

1. Получить разрешённый ответ по5записей из каждой таблицы и полную запись по одному ID. Подтвердить с поставщиком валюты/единицы цены, единицы мощности/объёма/пробега, значение даты, признаки удаления/продажи, правила пользовательских запросов и допустимого кэширования и общий лимит трёх рынков. Не подменять исходную цену японским FINISH по предположению.
2. Нормализовать в существующий VehicleOffer с отдельным sourceId, происхождением каждого параметра и сохранённой внешней идентичностью. Не выдавать пиковую мощность за30-минутную. Не выдумывать VIN, дату производства, топливо, массу или URL источника.
3. Использовать существующие правила возраста остальных рынков (не старше6календарных лет), исключения тяжёлой техники и существующий расчёт доставки/пошлин. Японский минимум2008 на эти рынки не распространяется.
4. Выполнить ограниченные пользовательские поиски и открытия карточек, не подменяя Che168 и не загружая всю базу. Сравнить одинаковые объявления по подтверждённым VIN/исходному ID/URL; совпадение марки, модели и года само по себе не доказательство тождества.
5. Сравнить допущенный объём, пересечение и уникальные автомобили, свежесть и снятие, исходную цену и итог при одинаковых курсах/городе/профиле, заполненность топлива/мощности/объёма, фотографии. Сравнение по одной странице не объявлять сравнением полных баз.
6. Проверить отключение/возобновление, пагинацию живых запросов, честность неполного кэша, отсутствие дублей и сохранение ручных характеристик. Только после успешной проверки и решения владельца переключать текущий Китай. Сейчас его НЕ отключать.

## Ограничение текущей сессии

Образцы автомобилей не получены, сравнение данных не выполнено. Успешное подключение фидов не заявляется. Экспорт снимка настроек не выполнен: автоматическая проверка отклонила чтение вспомогательной документации cloud-shared-files как потенциальный доступ к приватным материалам вне задачи. Состояния выключателей подтверждены отдельным разрешённым чтением интерфейса.


## Уточнение: портал поставщика доступен по HTTP

17.10.2026 после уточнения владельца проверены публичные страницы `http://auc.avtocena.com/`, `/china`, `/korea`: все ответили HTTP200. Навигация главной содержит Корею131177 и Китай231017; страницы рынков содержат соответствующие заголовки. Это гостевой просмотр без авторизации. Он подтверждает наличие/доступность разделов портала, но не проверяет оплаченные API-разрешения и не заменяет образец API.

Браузер перевёл HTTP на HTTPS и показал502 с ошибкой проверки самоподписанного сертификата. Проверка HTTPS не отключалась. Исходный HTTP-адрес портала ответил независимо; автоматическое переключение браузера нельзя принимать за отсутствие кабинета.

Предыдущий visitor_restricted относится к API-запросу из текущего подключения. Делать из него вывод«Михаил не активировал рынки» нельзя. Новых API-запросов при проверке кабинета не было. Указанные объёмы не прошли наши фильтры, сравнение и импорт остаются открытыми.


## Исправление архитектурного плана после повторного чтения переписки

Владелец повторно предоставил исходную инструкцию17.10.2026: **полную базу загружать и затем обслуживать без запросов к поставщику запрещено**. Предыдущие формулировки про приёмочный полный импорт были ошибкой плана и отменены. Полный импорт не запускался. Правильная схема — SQL по действию посетителя, полная карточка отдельным запросом поID; кэш справочников, счётчиков и открытых карточек в разрешённых пределах.

Примеры https://ajes.com/api/search и https://ajes.com/api/sql2json прочитаны как исходный PHP-текст, не исполнялись. Оба указывают поддержку RU-сервера87.242.72.57; search перечисляет main/stats/one/korea/china/hdm. Режимы api/gzip поддерживаются; IP посетителя берётся из REMOTE_ADDR (или CF_CONNECTING_IP в соответствующем окружении), добавляется json. Это согласуется с выбранным сервером/режимом нашего клиента; не доказывает правильность фактического IP и сохранённого ключа конкретного запроса.

Проверка Китая шла через облачный браузер и нашу CRM, затем через сервер сайта. Код берёт x-real-ip; точное фактически отправленное значение не сохранено в результате этой проверки. Код bot/botN был сведён к visitor_restricted, точный суффикс также не сохранён. Поэтому пока нет запрошенного Михаилом полноценного диагностического набора: время, IP, SQL, HTTP-статус и точный безопасный код отказа без ключа. Это недочёт нашей диагностики, не доказательство неисправности фида поставщика.

8.1.1.1 в присланном примере — демонстрационный адрес, не подтверждённый IP нашего посетителя; не подставлять его для обхода отказа. Для точного количества нужны агрегаты с теми же подтверждёнными условиями допуска; если часть условий нельзя выразить в SQL, результат не выдавать за точный итог всех наших фильтров. Отказы Китая не распространять на непроверенную Корею.
