# Управление сбором каталога владельцем

Дата: 10.10.2026. Место: `/crm/site` → «Обновление каталога · парсеры и фиды». Статус выпуска проверяется в roadmap.md.

## Правила владельца

- Существующий репозиторий остаётся публичным. Второй репозиторий и платный GitHub не подключаем.
- Китай обновляется оплаченной выгрузкой Che168. Прямые Che168/Autohome — выключенный крайний резерв, включаемый только владельцем. Никакого автоматического перехода на парсинг при отказе фида.
- Общая база остаётся общей для дилеров. Переключатели не меняют курсы, таможню, утиль, коммерческие настройки, допуск источников или опубликованные машины.

## Рубильники

Общий переключатель рынка останавливает все входящие в него источники, сохраняя их индивидуальный выбор. После включения рынка выключенные источники остаются выключенными. Источники управляются отдельно, включая ProAuctions, дополнительную проверку JPTrade и зелёный угол Akebono.

Включение разрешает следующий плановый запуск. Для срочного запуска ссылка в разделе рынка открывает соответствующее задание GitHub; владелец с доступом к Actions выбирает Run workflow на main. Повторный запуск старого failed job не нужен: он может содержать старый код. Уже отправленный запрос может завершиться; обновлённые сборщики проверяют состояние перед очередной страницей/карточкой с кешем не более 5 секунд. Старые процессы до этого выпуска не приобретают новый код автоматически.

История последних 200 изменений, время последнего включения/выключения каждого рынка и источника и ID владельца сохраняются вместе с настройками. Начальное состояние не выдаётся за фактическое событие: у выключенных по умолчанию резервов показано решение владельца, а не выдуманное время нажатия.

Платный Che168 и его старый парсер используют общий inventory sourceId, но разные управляющие ключи. Одновременный сбор обоими запрещён: сначала выключить текущий источник, затем включить резерв. Autohome New может быть отдельно разрешён владельцем. При возвращении с резервного парсера на фид курсор старого парсера не принимается за paid cursor: сохраняются проверки snapshotBinding/provider/replica.

## Хранение и защита

`catalog/operations/collection-controls-v1.json` хранится в закрытом Object Storage. Сайт и GitHub читают один объект. Изменение защищено revision и ETag: устаревшее окно или конкурентный запрос не перезаписывает решение владельца. Только активный platform owner компании dealer_topavto имеет доступ к API; для PUT проверяется Origin, ответы private/no-store. Ошибка чтения либо повреждённый объект останавливает сбор, а не включает источник. Отсутствующий объект использует документированные начальные значения (фид Китая включён, его парсеры выключены).

Планировщики, приём страниц/деталей, платный приём и архивирование, ProAuctions, зелёный угол, целевое восстановление и автоматическое восстановление учитывают переключатели. Глобальный allowlist не урезается по выключателям: иначе потерялись бы сохранённые автомобили.

Служебные Yandex bridges требуют краткоживущую подпись запроса. Производный HMAC-ключ отделён контекстом от существующего storage credential; исходный ключ не передаётся. Подпись привязана к GET, пути, параметрам и времени (120 секунд). Действующие worker и web окружения уже имеют необходимые storage credentials. Адреса снятых с production Guazi, Goo-net и Prestige отвечают 410 без обращения к поставщику. Это не новые разрешённые источники; их старые реализации сохранены в коде для истории.

## Сбой фида

Неполная выгрузка, отказ доступа, ошибка схемы или оборванные изменения не переключают опубликованное поколение и не продвигают committed cursor. Повтор идёт от последнего подтверждённого состояния. Сайт читает опубликованную базу независимо от доступности фида/GitHub. Продолжают действовать возраст, подтверждённые снятия и сроки актуальности (сейчас non-Japan retention 14 дней); нельзя обещать бессрочное сохранение старого ассортимента. Мониторинг отмечает остановленный владельцем сбор, но не объявляет устаревшие машины свежими и не скрывает проблему из readiness.

## Добавление следующего фида

Добавить отдельный control ID типа feed и описать источник/расписание/ограничения в collection-controls-schema.ts. Подключить тот же assertCollectionEnabled к сетевому пути и планировщику. Для нового формата настроек нужна явная миграция существующего объекта: неизвестные/отсутствующие обязательные поля не должны включать сбор. До замены парсера проверить полноту, идентичность, фото, цены, удаление и завершённую публикацию по paid-feed-integration.md. Выключение заменённого парсера выполняет владелец либо ассистент по его явному поручению.

## Оптимизация этого выпуска

Поисковый selector v2 хранит названия полей один раз, сохраняя значения, отсутствие/null, порядок, все рынки и расчётные входы. Карточки, формулы и пагинация не изменены. Перед маркером готовности проверяются целостность, поколение и количество; старый v1 сохранён для предыдущей версии сайта/отката. Повреждение или отсутствие v2 возвращает прежний точный путь.

Почасовая проверка подготовки цен запускается в GitHub. Готовность зависит от реально развёрнутого SHA, поколения, курсов, даты, настроек и версии selector. Если publisher занят, проверка фиксирует deferred/ошибку и повторяется по расписанию. Если тот же контекст уже проверен менее 20 часов назад, тяжёлая работа пропускается. Готовность фиксируется после независимых проверок поиска в холодном процессе. Снижение production CPU/latency и рублёвую экономию подтверждаем отдельно по замерам и сопоставимому биллингу.

Старые source readiness/probe/diagnostic задания (включая Guazi/AutoScout и API-диагностику Che168) больше не запускаются от push общего кода. Они сохранены для явного ручного исследования; плановое обновление выполняется только штатными рыночными workers. Обычные offline CI/проверки интерфейса не отключены.

Изменения только workflow/документации больше не пересобирают и не перезапускают web-контейнер. Если изменён только deploy-yandex.yml и необходимо применить его параметры окружения/ресурсов, нужен явный Run workflow; изменения приложения по-прежнему развёртываются автоматически. Это исключает повторный deploy сайта ради настройки диагностических заданий.
