# Короткие уведомления CRM через GitHub

## Подключение
1. В Settings → Secrets and variables → Actions репозитория jeep-jim/AvtoCena добавить repository secret `TELEGRAM_BOT_TOKEN`: действующий токен @avtocena_bot. Не публиковать токен в чате, issue, коде или логах. Уже используемый `AUTH_ACCESS_KEY` должен совпадать с production.
2. Повторить проверку getMe в диагностическом workflow. До публикации можно повторно выполнить job 104207695444 run 34914055410: он проверяет Telegram и не отправляет сообщения.
3. После полного зелёного CI и успешной проверки токена слить обычный PR. Дождаться новой ревизии и проверить точный release SHA.
4. В Actions → CRM Telegram delivery retries → Run workflow сначала выбрать `check`. При необходимости выбрать `setup-webhook`: используется текущий URL и секрет из CRM, pending updates не удаляются.
5. Получатели входят каждый в свою учётную запись CRM и подключают свой Telegram по свежей личной ссылке. Проверить наличие Telegram ID и активную роль owner/admin. Один username без привязки не даёт права получать заявки. Диалог бота этим этапом полностью не восстанавливается; ответ о привязке может не прийти, состояние проверяется в CRM.
6. Создать явно обозначенную контрольную заявку и запустить `deliver`. Проверить сообщение у владельца и второго администратора, переход в защищённую CRM, sent/messageId в очереди. Затем архивировать контрольную заявку. Не считать ноль получателей успешной проверкой доставки.

## Поведение
- Используется существующая очередь. В GitHub передаются только идентификаторы задания/заявки, Telegram chat ID, короткий текст, ссылка и временный секрет резервирования.
- Каждые 5 минут планируется запуск, но GitHub может задерживать или пропускать cron. Мгновенная доставка не гарантируется.
- Права проверяются перед отправкой. Изменение прав после этой проверки, но до сетевого вызова, не может отозвать уже отправленное сообщение.
- Резервирование 5 минут, максимум 3 задания за batch; следующий запуск подхватывает оставшиеся. Отсутствие подтверждения после истечения резерва может привести к повтору. Telegram sendMessage не предоставляет используемый здесь ключ exactly-once.
- Ответы клиентов не передаются через этот worker. Перенос полноценного диалога — отдельный этап.
- Не создавать дополнительное расписание рынков и не менять каталог ради этого workflow.
