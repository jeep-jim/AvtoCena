## Независимость и восстановление

`.github/workflows/catalog-five-market-full-rebuild.yml`: одна матрица пяти collect, `max-parallel: 1`, `fail-fast: false`. Публикации ждут завершения ВСЕЙ матрицы сбора. Ошибка одного job не отменяет остальные (Европа/ОАЭ это доказали), но медленный сбор задерживает публикации других рынков. Япония и пять рынков используют общую workflow concurrency group `catalog-six-market-quality-rebuild`: они не независимы по очереди выполнения.

Повторы отдельных HTTP/Object Storage запросов есть. Автоматического исправления кода нет. Контроль свежести имеет только `contents: read`, записывает отчёт и возвращает exit 1; не запускает восстановление. [Run 35623042291](https://github.com/jeep-jim/AvtoCena/actions/runs/35623042291) обнаружил `japan_publication_pending_over_48h`, но не исправил проблему. Последние упавшие runs имеют run_attempt=1.

Рекомендованный ремонт: самостоятельный цикл collect → validate → publish для каждого рынка, отдельные run/checkpoint/статусы/повторы. Общую блокировку записи в Object Storage сохранить: раздельный сбор НЕ разрешает параллельную перезапись общего manifest. Повторять ограниченно только сетевые/временные ошибки; policy/price/identity guard не обходить. На повторяющейся ошибке оставлять последнюю рабочую публикацию и честный статус деградации. «Сам чинит любую поломку источника» технически не подтверждено и не обещается.

## Ошибка измерения свежести

`storage.ts` при сохранении поколения выставляет `updatedAt: now` всем markets, в том числе перенесённым без изменения. `catalog-operations-health.mjs` использует это поле как publishedAt. Лог 21.09 показывает одинаковое 03:47:56.543Z для шести рынков, несмотря на провал публикаций China/Korea/Georgia. Нужны независимые lastCollectionSuccess/lastPublicationSuccess/sourceObservedAt по рынку, не дата перепаковки общей generation.

## Потолок цены и 80/20

Просмотрены все 756 UAE через публичный search с фактической пагинацией 48. Найдены **55** карточек с sellerPriceRub > 15 000 000. Например [Lamborghini Aventador](https://avtocena.com/cars/offer/934cec57c7c016e15e1126f9): sellerPriceRub=77 980 188, sourcePrice=926 158 USD, totalRub=null. Это отображаемая цена продавца, не подтверждённая цена под ключ.

Причина: `classifyCatalogV2Offer` проверяет потолок по totalRub, `prepareSellerInventory` переводит неполный расчёт в seller-only и убирает totalRub. Для sellerPriceRub аналогичного gate нет. Бюджетный фильтр по готовой стоимости возвращает ноль таких машин — это не доказательство их отсутствия в каталоге.

В `china-owner-policy.ts` остаётся 16 млн для Китая; новое требование владельца — 15 млн для всех. Необходимо проверять и итог, и доказанную минимальную стоимость (цена продавца уже выше лимита заведомо не подходит), не выдумывая полный расчёт там, где нет параметров.

`power-mix.ts` освобождает неизвестную мощность seller-only от квоты вне Китая; старые retained high/unknown также могут превышать allowance. В опубликованном UAE report: low=109, high=27, unknown=620, targetMet=false. Europe: low=12 961, high=3 240, unknown=5 242, targetMet=false. Программа честно выставляет false, но публикация из-за этого не блокируется. Япония явно исключена из 80/20 по прежнему правилу владельца.

Нельзя одновременно немедленно сделать 80/20 и гарантировать сохранение текущего количества, если нет достаточного объёма проверенных low-power машин. Безопасная последовательность: восстановить обновления и параметры, собрать/дополнить low-power запас, проверить будущий состав без записи, переключать только после достижения порогов. Не маскировать неизвестную мощность значением 100 л.с. и не массово скрывать текущий каталог ради отчётной доли.

## Критерии завершения следующего ремонта

1. Ни один обычный неполный проход не уменьшает опубликованный допустимый ассортимент; последний хороший manifest остаётся активным до полной проверки.
2. Каждый рынок независимо собирается, восстанавливается из checkpoint и публикуется через общий writer lock; падение одного не задерживает публикацию других на полный цикл.
3. Проверка freshness основана на реальном успехе рынка и источника, а не перепаковке.
4. Продемонстрирован успешный resume Японии без 512 MiB ceiling и без повторного скачивания уже сохранённого прогресса.
5. Лимит 15 млн закрывает seller-only обход. 80/20 считается от полного публичного рынка, неизвестная мощность — не low. Переход выполняется с предварительным подсчётом и без скрытого обвала.
6. Проверены обычная публикация, сетевой сбой, нулевой источник, провал квот, потеря блокировки и повтор выполнения. Ошибки источников не объявляются автоматически исправленными только по зелёному workflow.
