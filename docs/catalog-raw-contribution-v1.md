# Independent source contribution, version 1

This source-only protocol now connects two producers: a full paid Encar snapshot
restored from saved pages and the verified independent Che168 SQLite replica.
It does not collect another feed, change publication selection or merge results,
edit prices or manual specifications, activate coordination, or delete objects.
Europe, Georgia and UAE materialization proofs remain pending. A complete input
archive or replica alone does not prove independence of the final catalog rows.

## Source boundary

The existing Encar restorer reads the exact snapshot pages sequentially. Its
optional `paidInputWitness` binds the complete document, the ordered actual page
hashes, raw row count, and the final normalized unique `[id, rowSha256]` pairs.
The full serialized normalized row is hashed, including its prices, observation
dates and provenance. The actual mapper still rejects undocumented thirty-minute
power. The converter independently checks the final deduplicated SQLite rows.
An input proof mismatch removes only this optional retirement evidence; it does
not substitute rows, weaken ordinary admission, or label a partial feed complete.

The workflow owner and source checkout are separate identities. The witness
records the actual clean tracked checkout SHA. It is unavailable if the source
closure is dirty or its required normalization files are untracked. Publication
also records the worker checkout SHA and the existing calculation-version hash.

The witness must be present in the immutable archived `report.json`. Publication
reads that exact archived report, checks every bounded gzip part and file hash,
then checks the saved snapshot complete document again. No supplier call is
part of this path.

## Publication boundary

The normal publisher observes each existing merge. Paid Encar rejects any
retained argument. Che168 compares the exact actual merged bytes with the same
commercial merge run on the fresh input and an empty retained object. The empty
object contains no old data and reproduces that branch's null/empty-object
handling. This baseline is a closed audited function, never a caller callback.
Any retained byte contribution, changed incoming row, untracked selected row,
technical repair, delta, partial input, archive dependency or missing witness
leaves the old dependency union intact. Existing photo removal and contradictory body-default clearing
remain allowed selection transformations; they cannot add borrowed fields.

The normal prewrite and final-public callbacks capture the actual normalized
and compact public bytes. Before internal CAS, every reusable Encar chunk and
row must match those captured normalized bytes. An extra internal-only old ID,
different bytes under the same ID, an unproven K Car reserve, or a missing chunk
prevents a full-replacement proof. This initial producer conservatively declines
proof if an internal-only fresh row was not observed by the normal public-eligible
normalization callback.

After public chunks and the immutable projection exist, the second phase checks
every compact public row, the projection's exact ID coverage, the actual internal
manifest, and the first phase again. Only that verified in-process capability
can replace the proven target market's old raw dependency union. Ordinary public-count, price,
manual-repair, source-enable, import-lease, prepared-budget and CAS guards keep
their existing behavior.

## Durable format and carry-forward

Objects are create-only under:

`catalog/raw-feed-coordination/v1/contributions/<generation>/<source>/`

The control namespace keeps a carried source proof independent of ordinary
generation cleanup. Its row parts contain only IDs and input/normalized/public
hashes. They include all normalized input IDs; an excluded row has null output
hashes. Each part has at most 500 rows and 4 MiB. The Encar proof admits at most
500,000 unique normalized rows and 100,000 saved pages; these are proof limits,
not new collection or publication quotas.

`internal.json` binds the archived input witness, every materialization part,
the original internal manifest hash, the exact source-entry hash and actual
internal chunk hashes. `manifest.json` binds the same materialization and
internal receipt plus actual public chunks and manifest. All paid observation
report roots are included. The version-2 public provenance records the immutable
`contributionReferences`; it does not accept an extra caller completeness flag.

The generic application reader independently checks the persisted chain and
actual chunks. An unchanged source may carry its proof into another global
generation only when its source entry and chunks remain byte-identical. Every
nonempty internal source still needs its own verified contribution before the
flat historic union can be retired. Unknown sources retain the old roots.

Control-witness compaction is a separate future retention operation. This change
does not extend any deletion namespace or make the dormant raw GC executable.

## Private source-processing authority

The shared `catalog-source-contributions.mjs` protocol holds each factory
tracker's state reader in a private WeakMap. Its public `snapshot()` is an
inspection copy and is never an input to either immutable materialization
stage. An invented object, an overridden snapshot, or a different tracker
cannot mint the original tracker's proof. The internal capability is bound to
that exact tracker and its captured state digest.

Internal and public byte verifiers, proof bodies and reference addresses are
also stored privately. Public `verify()` properties are convenience wrappers;
publication never invokes a caller-replaced property or consumes mutable
public proof metadata. Both phases and every final publication verification use
the closed verifier and return copies of its verified references. The full
reusable market-source list cannot be reduced through an optional argument.

Regression cases reproduce the independently reported invented snapshot,
mixed tracker and overwritten verifier failures, plus replacing a valid
tracker's snapshot and mutating its private processing sequence after the
internal phase. The paid profile retains its strict no-retained-merge policy;
the optional shared exact fresh-only comparison does not change catalogue rows.

## Trusted protocol instances and internal cutover

The generic factory does not register an authority. Each instance owns separate
private tracker and capability maps. `catalog-source-contribution-authority.mjs`
selects only the closed paid Encar and Che168 wrappers; an arbitrary profile with
permissive validators cannot grant retirement authority even if it writes
structurally valid, byte-consistent proof objects.

New internal cutovers accept `contributionCapabilities`, verify the exact
manifest/intake/private tracker and reread the immutable input/output, then take
references only from private fields. New plain `contributionReferences` are
rejected before provenance writes. The helper copies the capability array and
rechecks the closed verifiers before each internal manifest commit. Previously
persisted contributions follow a separate carry path: their exact source entry
and actual chunks must remain unchanged. Unknown sources keep the old flat union.

Regressions exercise a permissive rogue factory with unchanged source witness
and retained manual/power values: its own byte reader can validate its objects,
but both public and internal trusted dispatchers reject its authority. Other
regressions cover a mutated verifier array, replaced public properties, source
entry changes and the legitimate unchanged carry-forward path.

## Actual Che168 source path

The completed future-main collector emits `sourceInputWitness` after closing
SQLite and verifying the saved current replica. The existing immutable intake
archive includes that report. The ordinary converter checks its final unique
SQLite payloads against the witness; mismatch strips only optional evidence.
The standard publisher supplies the closed Che168 tracker to the same audit,
selection, normalization, internal CAS and public callbacks used for paid Encar.
The fixed reusable source scope includes used and new China inventory; an
unproven nonempty second source prevents complete replacement.

Tests restore a real SQLite replica, archive its report, execute the real
converter and the actual common commercial merge, then validate both proof
phases through the generic reader. Old first-seen dates, additional photos,
manual/power fields, an old price when fresh price is null and extra operational
raw fields all keep the old union. Successful proof retains current replica,
journal, snapshot-config and own-archive roots. It never changes current or
previous pointers or deletes objects itself.

This wiring is not writer-coverage proof or GC activation. Legacy jobs, all
seven actual pointers, persisted coordination bootstrap, unknown internal
sources and Europe/Georgia/UAE lineage remain independent requirements.
Paid report roots remain explicitly protected for unfenced VM readers.
