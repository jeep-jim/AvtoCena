# АвтоЦена: автономная работа семи рынков

Актуально с 17 августа 2026 года. Этот файл — передаваемый контекст для нового чата и краткая эксплуатационная инструкция. Репозиторий: `jeep-jim/AvtoCena`.

## Что считается нормальной работой

Публичный каталог — не вечный архив и не счётчик «только вверх». Каждый рынок ежедневно получает свежие предложения, а публикация объединяет их с ещё живыми предложениями предыдущих запусков. Для активных объявлений Кореи, Китая, ОАЭ, Европы и Грузии окно удержания — 3 суток (`CATALOG_OFFER_RETENTION_MS=259200000`). Японские Prestige/AJES sold-лоты являются аукционной статистикой, поэтому для них действует отдельное окно 30 суток (`2592000000`). Число карточек всё равно может умеренно меняться: вышедшие из окна записи удаляются, новые входят.

Общие обязательные правила:

- шесть рынков: Япония, Корея, Китай, ОАЭ, Европа и Грузия;
- не более 20 карточек на точную комбинацию `рынок + марка + модель + год`;
- 5–30 подтверждённых фотографий автомобиля на карточку;
- Япония допускает последние 15 модельных лет, остальные рынки — с 2020 года;
- все production-писатели используют один общий lock `catalog-live-daily-working-markets` и не отменяют уже начатую публикацию;
- после публикации выполняется строгий аудит; чужие рынки должны сохраниться;
- отдельная ошибка одного вторичного источника допустима, если рынок собран другими источниками и итоговый аудит зелёный.

## Источники

- Корея: Encar, K Car, KB ChaChaCha.
- Китай: Autohome used/new, Guazi, Dongchedi. Dongchedi иногда требует login challenge; это не авария, если остальные источники обеспечили зелёную публикацию.
- Европа: mobile.de, AutoScout24, OTOMOTO.
- ОАЭ: DubiCars и Dubizzle. Один источник может временно отказать независимо.
- Грузия: только канонические `myauto_georgia_list` и `autopapa_georgia_open` через Yandex v2. Старый direct workflow не должен запускаться автоматически.
- Япония: только подтверждённые Prestige/AJES sold/detail/gallery данные. Ежедневный запуск обходит разные группы моделей, а 30-дневная публикация объединяет результаты. Это окно относится к лотам внутри текущего каталога, а не к хранению 30 полных поколений.

## Почему рынки разного размера

`30 000` — верхняя граница рынка, а не обязательный результат. Итог зависит от доступности источников, числа реальных объявлений нужных годов, подтверждения точной модели и галереи, лимита 20 на модель-год и окна удержания: 30 суток для японской sold-статистики, 3 суток для остальных рынков. Поэтому Корея может давать 12 тысяч, а Грузия — заметно меньше; это нормально при зелёных quality gates.

## Защита от поломок

1. До записи проверяется текущий all-6 baseline.
2. Сборщики создают артефакты и сами по себе production не меняют.
3. Публикация сериализована общим object-storage lock.
4. Грузия обязательно проходит dry-run и запрет уменьшения перед apply.
5. Япония до записи не может уменьшиться более чем на 10% относительно текущей опубликованной японской выборки.
6. После записи проверяются возраст, identity, изображения, квота 20 и наличие всех семи рынков.
7. `catalog-global-model-cap.yml` после writers повторно приводит весь каталог к квоте 20 и снова проверяет шесть рынков.
8. Старый `catalog-live-recovery-uae-georgia-direct.yml` остаётся legacy/manual и не должен автоматически вызываться.

## Что смотреть при красном запуске

1. Открыть GitHub Actions и определить конкретный workflow и job.
2. Отличать красный source-shard от красной публикации/final audit: отдельный источник может быть ожидаемо недоступен.
3. Не запускать параллельно другой production writer и не удалять object lock вручную без проверки.
4. Для Грузии использовать только Yandex v2 workflow; ручной запуск по умолчанию `apply=false`.
5. Для Японии не возвращать монолитные 220 partitions и `cancel-in-progress=true`: именно это приводило к четырёхчасовым отменённым запускам.
6. Если упал сайт, сначала проверить Yandex API Gateway (Active), Serverless Container, Certificate Manager и баланс. Cloudflare для `avtocena.com` в этой схеме не используется.
7. После исправления требовать свежий `catalog-live-postpersist-audit.mjs` с `failures: []` для всех семи рынков.

## Команда новому чату

> Прочитай `docs/AVTOCENA_MARKET_AUTONOMY.md`, проверь текущий `main`, последние scheduled runs перечисленных workflow и all-6 audit. Не меняй Encyclopedia-ветку и не запускай legacy direct Georgia. Если проблема только в одном source-shard, сначала проверь итоговую публикацию и audit; исправляй лишь реально сломанный источник.

## Граница с Энциклопедией

Энциклопедия разрабатывается отдельно в ветке `feat/encyclopedia-knowledge-base`. Рыночные расписания продолжают жить на `main`; сбор базы знаний не должен запускать рыночные writers и не должен менять production-каталог до отдельного осознанного merge/deploy.
