## Япония: подтверждённая исходная проблема

- Поставщик уточнил: PW — целое значение в л.с., нескольких значений нет. Полученная [структура AJ](https://ajes.com/api/aj_bids.txt) хранит PW как `varchar(30)` с описанием engine power: числовое значение может прийти строкой. Прежнее правило выбора первого из нескольких PW заменено строгим целым значением.
- [Обычные public GET в 11:41](../operations/2026-11-26-japan-recovery-baseline.json): без мощности получено 24 строки, показано 23 автомобиля, stale=false; с powerTo=160 получено 24 строки, показано 0, partial/stale=true. Ответы имеют разные observedAt, их состав не объявляется одинаковым. Длительности 5,4484 и 8,5013 с — отдельные наблюдения, не эталон скорости.
- В коде d536 поле PW читается из источника, но не попадает в отображаемую мощность; локальный фильтр отбрасывает автомобили без обогащённого powerHp. Найдены также условия, скрывающие японскую ленту при пустом ответе/ошибке настроек и фильтрах главной.
- Подготовлен [immutable runtime 9c2a2bb55](https://github.com/jeep-jim/AvtoCena/commit/9c2a2bb55aec0a1d68d12b9744dff164b9dda053), ровно 37 файлов от d536: rails главной/каталога, строгий PW с пометкой поставщика, неизвестные значения и честные счётчики, повторное использование запрошенной страницы при смене локального фильтра. [Проверки кандидата](../operations/2026-11-26-japan-candidate.json): 386/386 native tests, 57 файлов, без compatibility patch; web typecheck; защищённые pricing paths и speed baseline неизменны. На сайте ещё не установлен, обязательные live gates впереди.
- Сохранять приоритет подтверждённых/ручных характеристик. Отсутствующую мощность показывать как неизвестную; включение такой машины в предварительную подборку не подтверждает порог или льготный сбор.
