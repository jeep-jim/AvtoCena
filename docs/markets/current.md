**Обнаруженная возможная причина в клиентском коде:** при открытии карточки с явным городом `CitySelector` на mount читает глобально выбранный город и может вызвать новый расчёт; подписка на текущие курсы также могла вызвать непрошенный перерасчёт. Точная клиентская последовательность ещё не доказана и должна пройти отдельный тест. В main внесён целевой фикс: `c8f7c0f` (правило города), `f74ec0d` (закрепление и отсутствие автоматической переоценки), `6ce688a` (передача контекста страницы), `6e47fae` (тест), `381ec5c` (отдельный CI без деплоя). В контроллер `835f812` добавлен диагностический вывод ожидаемой и видимой цены при следующей проверке, без отключения обязательной проверки. **Эти коммиты ещё не являются установленным runtime сайта.** Первичная проверка main №45542018063 указала на расхождение типов старой страницы main с закреплённым новым runtime — изменение страницы main отменено. Точный кандидат исправлен в [ветке `fix/china-detail-frozen-city-20261125`](https://github.com/jeep-jim/AvtoCena/tree/fix/china-detail-frozen-city-20261125) от `38895e53`; [проверка №45542253549](https://github.com/jeep-jim/AvtoCena/actions/runs/45542253549) **успешна** (3 целевых теста и typecheck). Этот результат доказывает только код и типы, **не реальный браузер с полной генерацией**. Перед следующим дорогостоящим выпуском нужен быстрый браузерный preflight точного кандидата с явным городом, другим сохранённым городом и новым курсом, проверяя видимую цену против Oracle.
