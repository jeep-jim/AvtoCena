## Причина и граница исправления

- В665 свежий справочник давал `model:A4`, stale/missing ветка добавляла `modelFamilies:A4`; это меняло hash курсора при тех же пользовательских фильтрах. Точные старые hashes и отказ до чтения следующего LIST воспроизведены локально. Отказ поставщика или bot этому HTTP409 не приписываются.
- Новый resolver сохраняет literal/family predicate при смене доступности справочника. Реальное изменение набора нелитеральных aliases продолжает требовать обновления первой страницы. Принудительные fresh/stale/missing переходы проверены в offline Chromium; на live проверялись обычные действия пользователя.
- Первый кандидат остановился в [CI 46136141592](https://github.com/jeep-jim/AvtoCena/actions/runs/46136141592) на трёх старых assertions формы descriptor. Их заменили проверками фактических SQL LIST/COUNT строк; production-файл после первого кандидата не менялся. Итоговый CI выше прошёл полностью.

## Счётчик и незавершённые требования

- Интерфейс различает точный `Найдено N`, полную исходную верхнюю оценку `Найдено до N`, неполную исходную область `В источнике: N` и `Показано M · общий итог уточняется`. Сохранённые старые значения показывают исходную дату; отказ обновления не делает их свежими.
- Общий положительный admitted census отключён нашим алгоритмом: `sourceCount.total > 0` отклоняется с `census_source_snapshot_unavailable`. Это ограничение реализации, **не подтверждённый запрет поставщика на COUNT**. Общий census по доставленной цене отклоняется с `census_price_count_unavailable`.
- Точный результат допускается для доказанного свежего нуля в полной исходной области либо небольшой полной выборки из одного свежего LIST без power-фильтра и продолжения. Общий точный итог после всех фильтров, полнота локального отбора и глобальная сортировка по доставленной цене остаются открытыми. `finish_rub` не объявляется доступным, полный обход AJ не выполнялся.
