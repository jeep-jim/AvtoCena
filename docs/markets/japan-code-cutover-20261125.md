## Подтверждённая зависимость, блокирующая простой push/deploy
В `main` файл `.github/operations/catalog-next/china-serving-plan.json` закрепляет `runtimeSha=d536c154...`. Действующий `scripts/catalog-next/daily-release.mjs` требует равенства `candidate.runtimeSha === prior.current.runtimeSha`. При смене code runtime на `c8b9d312...` обычный daily перестанет соответствовать точному принятому runtime, пока не будет выполнена согласованная смена controller/serving-plan.

Текущий `scripts/catalog-next/release-host.py` имеет разные пути для новой полной China generation и data-only смены. Повторная загрузка принятой `details.sqlite`/`query.sqlite` лишь ради японского UI запрещается как необоснованная запись и расход диска. Старый общий publisher также не использовать.

## Требования к отдельной code-only публикации
1. Новый проверенный образ точно из `c8b9d312...`; неизменные параметры расчётов, source, энциклопедия, CRM и нет загрузки/пересчёта Китая.
2. Подхват уже действующего принятого China generation read-only с проверкой ID, SHA-256 манифеста, mount/env и идентичности образа; учесть обновления `catalog-next-china-daily` и существующие CAS/lock.
3. Обновление serving-plan и согласование daily-controller с новым SHA — только как часть контролируемого перехода, без окна, когда плановый China daily пишет в несовместимую версию.
4. Новый кандидат за ingress: полная проверка неизменности China IDs, готовых цен, фильтров/сортировки, главной и деталей; Япония видна при задержке и пустой первой странице, 160 л.с. не отключается, предварительное `PW` не участвует в таможне/утиле.
5. Переключение по точному CAS с браузерной приёмкой Японии и Китая. При отказе автоматически вернуть прежний ingress и прежний controller/accepted-state, не терять китайский dataset и японские разрешённые ответы.
6. Только после подтверждённой приёмки — запись `production accepted` в `docs/markets/current.md` и переход к Корее.

**Статус:** на момент подготовки этого документа публичное переключение не подтверждено. Результаты offline CI, read-only preflight и новой сборки не должны отображаться как «Япония уже выпущена». Первый реальный ежедневный China refresh после 21:00 Asia/Krasnoyarsk требует отдельной проверки.
