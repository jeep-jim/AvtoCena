# Квалификация источников каталога — контракт v1

Дата решения: 2026-09-03.

## Цель

Найти для каждого из шести рынков АвтоЦены источники, которые позволяют собирать доказанные карточки и выполнять корректный расчёт без угадывания характеристик. Production-каталог остаётся неизменным, пока новый набор не пройдёт no-write проверку и ручной semantic audit.

Активные рынки: Корея, Китай, Япония, ОАЭ, Европа и Грузия.

## Важное различие

Квалификация площадки не означает автоматического доверия всем её объявлениям. Она только разрешает направлять объявления площадки в offer-level gate. Каждая карточка проверяется отдельно.

## Классы источников

| Класс | Разрешённое использование |
| --- | --- |
| `exact_catalog` | Источник может давать карточки с автоматическим расчётом, но только после offer-level gate. |
| `lead_only` | Источник может использоваться для поиска предложения и заявки менеджеру; полный автоматический расчёт запрещён. |
| `rejected` | Источник не используется: нет устойчивого доступа, идентичности объявления или требуемых данных. |
| `research_pending` | Кандидат ещё не проверен; production-доступ запрещён. |

## Обязательный source-level probe

Для кандидата сохраняются дата проверки, публичный URL, условия доступа, тип выдачи, detail URL, стабильный sourceOfferId, наличие list/detail identity и результаты повторных запросов. Login wall, bot challenge, запрещённый robots route и нестабильный shell фиксируются как ограничения; защита не обходится.

Источник не получает `exact_catalog`, если его detail-представление не позволяет получить:

1. стабильную идентичность объявления и прямую source URL;
2. марку, модель и год;
3. фактическую цену предложения/завершённой продажи и валюту;
4. точный тип кузова;
5. точный fuel/powertrain;
6. точный `engineCc` для ДВС либо доказанное `not_applicable` для EV;
7. точную мощность из source-bound поля;
8. certified/utilization/30-minute power для тех EV/Hybrid, где она требуется расчётным контрактом;
9. фотографии той же машины и подтверждение их привязки;
10. достаточно данных для непротиворечивого полного расчёта.

## Offer-level exact gate

Карточка проходит только при одновременном выполнении всех условий:

- list/detail identity не конфликтуют;
- source price положительна, валюта известна, `priceMode=fixed`;
- кузов входит в канонический справочник и взят из однозначного поля;
- `year`, `fuelPowertrain`, `engineCc`, `powerHp` имеют состояние `exact`, а неприменимое поле — только `not_applicable`;
- диапазоны (`0–1499 cc`, `300–399 HP`), модельные средние, representative power и `review`-версии запрещены;
- EV/Hybrid не проходит без требуемой доказанной certified power;
- не менее пяти уникальных listing-bound изображений, кроме отдельно утверждённого auction-history контракта;
- итоговый расчёт завершён, не preliminary, содержит точный `totalRub` и разбивку обязательных платежей;
- карточка проходит общий public eligibility gate.

## Порядок проверки кандидата

1. Read-only access probe без production credentials.
2. Проверка структуры list и detail, identity и source price.
3. Выборка реальных объявлений разных марок, годов, кузовов и силовых установок.
4. Автоматический отчёт по каждому обязательному полю: `exact / ambiguous / conflict / missing / not_applicable`.
5. Ручная сверка карточек с detail-страницами; формальный зелёный отчёт без этой проверки недостаточен.
6. Фиксация класса источника и причины решения в candidate ledger.
7. Только для `exact_catalog`: адаптер, тесты, полный no-write run и повторный spot-check.

## Граница публикации

- Исследование, probes и dry-run ничего не удаляют и не пишут в production Object Storage.
- Текущие индексируемые страницы и public generation сохраняются.
- Новый рынок собирается поверх и переключается атомарно только после отдельного отчёта.
- Китай и Япония на текущем этапе могут исследоваться, но не публикуются.
- Подключение платного API допускается только после проверки, что API отдаёт source-bound факты; API поиска или сопоставления не имеет права изобретать отсутствующие характеристики.

## Текущий baseline

- Workflow `33717909118` — диагностический четырёхрыночный exact dry-run.
- Europe: формальный результат `1500`, но найден semantic false positive Mobile.de `Limousine → sedan`; результат не готов к публикации.
- UAE: `0` прошедших карточек; DubiCars — `270` просмотренных, Dubizzle — `9 883` просмотренных. Требуется повторная квалификация, а не ослабление exact gate.
- Mobile.de fix: commit `66e236c7`, неоднозначный `Limousine` больше не публикуется как седан.
- Korea и Georgia в указанном baseline на момент записи ещё выполняются.

## Следующее действие

Создать candidate ledger по всем шести рынкам. Для каждого кандидата указать URL, происхождение цены, доступность обязательных полей, доступ/лицензионные ограничения, класс и проверяемые причины решения. Сначала исследовать площадки; код адаптера писать только после прохождения source-level probe.
