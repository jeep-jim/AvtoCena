## Как вносить данные

1. Проверять текущую версию main и уже выполняющиеся исследовательские workflows. Не запускать параллельную запись по одному набору моделей.
2. Публичное чтение текущего года модели: https://avtocena.com/api/encyclopedia/{modelId}?year={year}; известные годы есть в очереди. Это наша собственная сохранённая энциклопедия. Не скачивать массово платные партнёрские фиды и не копировать их в публичный git.
3. Искать первичные заводские спецификации, руководства, сертификацию. Проверять реальные таблицы, даты, годы, модификации, тип силовой установки. Хранить факты и ссылки, не полные защищённые руководства. Не обходить ограничения источников.
4. Пакеты docs/encyclopedia/batches/*.json содержат максимум64 записи, точную идентичность и SHA256 наблюдавшейся исходной модификации (digest из scripts/encyclopedia/research-batch.mjs), подтверждённые patch/confirmedFields и source. Не выдумывать названия комплектаций; китайские исходные названия остаются во внутренней истории, отображаемый trim переводится без потери различий.
5. Сохранить существующие примечания и неперезаписываемые ручные правки. Статус строки review: отдельное подтверждение одного поля не делает всю строку verified. researchEvidence/history поддерживает полевые источники. Новый общий редактор пока может убрать эти метаданные при ручной замене варианта — нельзя в будущем использовать старые подтверждения без сверки текущего значения/идентичности.
6. Запустить tests/encyclopedia-research-batch.test.ts и проверить dry plan по свежим чтениям. Публиковать только проверенный пакет, необходимые правки инструмента и roadmap. Маркер .github/market-runs/encyclopedia-research.json (путь + digest всего пакета) запускает существующий workflow. Доступ к GitHub — native connector; секреты не извлекать.
7. Workflow пишет только энциклопедию в существующее объектное хранилище, создаёт ревизии, проверяет CAS/предусловия, журналирует точные результаты. Не запускает коллекции, публикацию каталогов или deployment. Проверить job success, число фактических изменений/пропусков, затем повторно прочитать API.
8. Обновить очередь, журнал источников/пропусков, roadmap под актуальной датой Asia/Krasnoyarsk. Никаких обещаний полной готовности без фактической проверки.

## Расчётные ограничения

- Не выводить30-минутную мощность из пиковой, номинальной или батареи. В руководствах M5/M6 есть номинальные моторные значения, но нет явного30-минутного подтверждения — они не перенесены.
- Нетто110кВт и номинальные112кВт ДВС не смешивать без выбранного подтверждённого стандарта; значения пока в примечаниях, engineCc/engineCode — структурированные факты.
- Не переносить технические параметры между разными годами/поколениями/рынками исполнения/батареями. Страна не является навигационной идентичностью модели, но различия технических исполнений существуют.
- Не восстанавливать недоверенные UAE feed hp/cc. Подключение именно проверенной базы пользователь разрешил, но техническая интеграция ещё не реализована.
- Не объявлять неполный расчёт окончательной ценой. Ручные данные имеют приоритет.
- Подключение движка — отдельный проверяемый этап: точное однозначное совпадение и заполнение только пустых полей, полевые источники, подготовленный версионированный индекс/память, без сетевого поиска и полного сканирования энциклопедии на карточку. Нужны тесты неоднозначности/года/ручных правок/единиц/30мин и штатная подготовка индексов при релизе. Не использовать старый UI-only release для обхода расчётной подготовки или locks.
