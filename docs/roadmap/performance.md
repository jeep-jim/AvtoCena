Обновлено: 22.11.2026. Новое ускорение ещё не подтверждено на production.

## Точная база

Live: `22867cbcfaee27b2e8917b6bf880e44827f67b60`. Исходный main: `702c7c85efb2a8d953f7e1c72f6f4713070d61d5`. Они существенно различаются; весь main выпускать нельзя. Runtime исправления подготовлены отдельно от точного live.

## Подтверждённые узкие места

| Путь | Факт | Подготовленное решение |

| Главная и `/api/catalog/home` | Реальный ответ: 50 карточек, 699 555 bytes; вложенные служебные provenance | Payload 425 026 bytes, минус 274 529 (39,2%); значения и статусы evidence сохраняются |

| Корея, широкий фильтр | Старый selector без specificationFilterVersion=1 вынуждает читать все budget-card blocks | Проверять завершённость текущей публикации и подготовку selectors; не заменять ошибку пустой выдачей |

Сетевые времена из рабочей среды не являются серверными измерениями. В одном ответе home Server-Timing: read 1055,5 ms, pricing 310,8 ms; полное время из среды 9,318 s. Сокращение bytes само по себе не доказывает ускорение всех страниц.

## Индекс Китая

Runtime helper `prepared-china-filter-index.ts`: нормализованные параметры и позиции без фотографий/полных записей. Ref запечатывается в проверенную Directory. Заявленный повреждённый индекс отвергается; старые срезы без ref и неподдержанные запросы используют прежнюю корректную выдачу.

Первичные тесты: 17 000 записей → ready + 3 компактных объекта для выбора страницы; parity карточек, порядка и total по 13 сочетаниям фильтров × 4 страницы. Интеграция producer и hydration проверяется отдельно. Эти результаты не означают, что новый индекс уже создан для публичного Китая.
