# Ограничения источников при работе с фидами

Текущая задача — исправить существующие фиды, расписания, фильтры и скорость страниц. Она не меняет классы источников и не выдаёт новые разрешения на публикацию.

## Сохраняемые проверки

- Квалификация источника (`source-level`) и доказательства конкретного объявления (`offer-level`) проверяются отдельно. Доступная площадка сама по себе не подтверждает характеристики каждой машины.
- Источник должен давать проверяемую идентичность объявления и связанные с ним факты. Отсутствующие характеристики нельзя подменять догадками; исправление сбоя фида не ослабляет действующие условия допуска карточек.
- Реестр кандидатов не предоставляет автоматическое разрешение на публикацию: `publishAllowed=false` сохраняется до отдельного подтверждённого решения. Ранее ограниченный источник не становится разрешённым из-за успешного скачивания.
- Исследование, probes и dry-run не удаляют и не пишут данные в production Object Storage. Восстановление уже разрешённого фида проходит собственные проверки источника, полноты и безопасной публикации.
- Япония и свежий Зелёный угол не входят в текущие изменения фидов. Их сбор и публикация этой задачей не разрешаются заново.

## Где проверять контракт

- [Контракт квалификации источников](../catalog-source-qualification-v1.md) — правила source-level и offer-level проверки; исторические статусы внутри не считать разрешением на новую публикацию.
- [Реестр кандидатов и ограничений](../../data/catalog/source-qualification-v1.json) — классы, `publishAllowed`, режим восстановления и остановленные рынки.
- [Текущая задача](current-task.md) — границы этой работы. Полный исторический роад для применения этих ограничений не нужен.
