# Текущая задача: AJ System только для Японии

24.11.2026, Asia/Krasnoyarsk. Владелец назвал двух поставщиков:

| Поставщик | Рынки |
| --- | --- |
| Михаил — AJ System | Япония |
| Auto API | Китай, Корея, ОАЭ |

## Разрешённый шаг

Удалить AJ System из настроек платных фидов вне Японии и всех мест выбора поставщика. Сохранить японское подключение и доступ. После фактического выполнения отчитаться и ждать следующего поручения.

Удаление охватывает админские источники `ajes_china_feed` / `ajes_korea_feed`, формы подключения, сохранённые записи настроек и скрытые обращения к AJ из поиска, карточек, рекомендаций и прежних API. Старые записи истории остаются историей; они не дают разрешения включить удалённый источник.

## Границы

Сохранить остальные настройки, автомобили, платные фиды Auto API, расписания, энциклопедию и расчётные движки. Не удалять резервные парсеры или другие рынки по этому поручению. Не запрашивать поставщика ради проверки отключения.

## Статус

Код удаления принят в [PR #1860](https://github.com/jeep-jim/AvtoCena/pull/1860); полный CI и браузерная проверка формы прошли. После уточнения владельца подготовлен изолированный источник `fe289d7e3b6c4c4f1aaff7d5e56b329802d5cd7b` с явным отказом для удалённого AJ. Он остаётся прямой поправкой фактически установленного `22867cbcfaee27b2e8917b6bf880e44827f67b60`, без ускорения поиска Китая. Source/tree/diff проверены; публикация этой уточнённой версии ещё впереди.

В [запуске 45312083161](https://github.com/jeep-jim/AvtoCena/actions/runs/45312083161) миграция **применена**: удалены ровно два AJ-флага, ревизия настроек 18; японский доступ и остальные настройки неизменны. Приложение **не установлено**, переключение публичного сайта не выполнялось.

Несовпадение Docker image ID исправлено в [PR #1861](https://github.com/jeep-jim/AvtoCena/pull/1861). Диагностика принята в [PR #1862](https://github.com/jeep-jim/AvtoCena/pull/1862); оба полных CI прошли. [Запуск 45321457924](https://github.com/jeep-jim/AvtoCena/actions/runs/45321457924) подтвердил точное препятствие: `home_host_aj_http_china-ajes_timeout_no_status` — обычный поиск Китая после удаления obsolete source не ответил за 90 секунд. Приложение запустилось с правильным source, затем было убрано; `accepted=false`, `ingressState=retained`, `remoteClosed=true`. Настройки уже очищены, повторной записи не было.

Владелец повторно уточнил границу: только удалить больше не покупаемые источники, без ремонта поиска Китая. Подготовленное локальное ускорение чтения **не опубликовано и исключено из этого выпуска**. Для `source=ajes` вне Японии требуется ранний HTTP 410 `source_retired`, до обращения к каталогу или поставщику. Подмена удалённого источника другим поиском не нужна. Проверки AJ подтверждают этот отказ, сохранение Японии и авторизации; все исходные 17 server routes, 51 измерение и browser gates остаются обязательными. Подробности — [журнал 24 ноября](log/2026-11-24.md).
