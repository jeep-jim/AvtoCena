## 2026-09-16 — CRM noindex и подготовка Yandex SmartCaptcha

- Усилен запрет индексации: HTTP `X-Robots-Tag: noindex, nofollow, noarchive` для CRM, входа и служебных API. Существующие robots meta сохранены; robots.txt закрывает также `/crm` без завершающего слеша. Это не заменяет авторизацию и не удаляет уже проиндексированные URL мгновенно.
- Добавлен серверный учёт отправок за скользящие 24 часа: третья по одному объявлению (включая выбранное в Избранном) или четвёртая суммарно требует SmartCaptcha. В общей форме действует суммарный порог. Учёт — в общем хранилище с условными атомарными записями, по подписанному браузерному cookie и HMAC контакта. Перезапуск контейнера не сбрасывает счётчик. Повторы того же operationId с тем же содержимым не расходуют новый слот. Резервирование выполняется после валидации контактов до записи заявки; неудачная запись может оставить зарезервированную попытку.
- Все публичные формы используют единый обработчик: скрипт Яндекса загружается только после ответа сервера о пороге; после проверки повторяется исходный запрос. Отмена/ошибка оставляет поля заполненными. Сервер проверяет одноразовый токен и домен, при ошибке проверки новая заявка не создаётся. Ручное создание менеджером в CRM не ограничено.
- Доставка сохранённых заявок в группу и существующее объединение дополнений не изменены. Обычный просмотр каталога не загружает капчу.
- **Активация ожидает настройки:** создать SmartCaptcha с доменами `avtocena.com`, `www.avtocena.com`, включённой проверкой домена и выключенным тестовым режимом. Добавить GitHub repository secrets `SMARTCAPTCHA_CLIENT_KEY` и `SMARTCAPTCHA_SERVER_KEY`, повторно выполнить Deploy to Yandex Cloud. Пока обоих ключей нет — капча выключена; частично заполненная конфигурация блокирует отправку с понятной ошибкой. После активации нужна контрольная проверка реальным виджетом.
- Ограничение: это защита формы, не WAF/DDoS-защита. Смена и браузера, и контакта позволяет начать новый счётчик; IP не используется без подтверждённого доверенного заголовка прокси. Необходимо отдельно проверить защиту на границе Yandex Cloud. Старые неактивные записи счётчиков требуют политики очистки в хранилище.
- Проверки: тесты порогов/24 часов/Избранного, параллельных запросов, повтора/изменения operationId, смены cookie при прежнем контакте, неверного домена/токена, отказа Яндекса и конфигурации; регрессия объединения заявок и доставки уведомлений.
