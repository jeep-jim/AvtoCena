## Привязка моделей и точность MyAuto — 07.09.2026

В CORE подключён существующий resolver безопасных алиасов. Для Encar добавлен поиск по английскому семейству из точного `detail.category`: совпадают ID исходной строки, марка и модель списка/детали; убирается только явный суффикс поколения. Более широкая группа не подменяет модель: Grand Cherokee не становится Cherokee. Исходные названия сохраняются; коды комплектации/JATO записаны как ключи дальнейшего поиска, но не объявлены доказательством мощности.

На сохранённой свежей fixture — 11/20 связей моделей; на отдельном последующем сетевом проходе — 10/20. Это разные объявления, а не изменение доли на одной выборке. MyAuto в последнем проходе вернул 8 машин; модели связаны у всех восьми. **Новых точных расчётов нет.** У всех 18 связанных строк с распознанной моделью обоих источников отсутствуют проверенные варианты; у Encar нет мощности, у MyAuto — мощности и достоверного происхождения точного объёма.

Исправлена потеря semanticEvidence между MyAuto product snapshot и recovery-мостом. Оба пути используют одну подготовку характеристик после нормализации; неподтверждённое поле `engine_volume` не признаётся точным только потому, что содержит целое число. Явный `engine_cc` принимается при согласованных данных; конфликт остаётся конфликтом. Галереи сохраняются ссылками и при неуказанном режиме хранения. Развёрнутый мост ещё не обновлён: свежая диагностика зафиксировала старые `missing`-метки рядом с выведенными значениями 2000/2500. Исправление recovery проверено локально; живая проверка новой версии требует её развёртывания. Прямой запрос product API вернул 403; повторных прямых запросов не было. Отдельный workflow использовал заранее настроенный production-мост; его внутренний трафик отдельно не наблюдался.

Аудит всех загруженных вариантов CORE: 18 941 V2-запись `review`, 24 489 `source_observed`, 261 `verified`. Последние распределены: Japan 256, Europe 2, Global 2, United Kingdom 1. Статус `verified` сам по себе ещё не доказывает полную пригодность для расчёта конкретного объявления. Повышение статуса исследовательских записей без документов не выполнялось.

Следующая работа с данными теперь задана отдельной воспроизводимой очередью `data/catalog/research/restart-knowledge-link-gaps-v1-20260907.json`: исходный URL/ID, не хватает каких полей, установлена ли модель, сколько её вариантов проверено, коды комплектации при наличии. Генератор — `node --import tsx scripts/catalog-audit-restart-knowledge-links.mjs` после общей сводки. Сначала нужны применимые проверенные характеристики и связь объявления с точной модификацией; затем новый ограниченный расчётный проход. Общий restart, публикация и расписания остаются на паузе.

## Что требуется до перезапуска

1. Закрыть замечания визуального просмотра: реклама, разнообразие кадров и спорная идентичность галереи. Изолированная техническая генерация и откат уже прошли; deployed web container пока не обновлён.
2. Для выбранного источника проверить актуальность и снятые объявления, реальные изображения, дедупликацию, совпадение настроек CRM и цен страницы/карточки. Затем оценить минимум 80% автоматических расчётов на принятом свежем наборе; пользовательские сценарии не входят в числитель.
3. Принять решение о публикации проверенной генерации. Массовое включение пяти рынков сейчас не готово; Корея через KCar и Европа через mobile.de продвинулись до кандидатов на следующий ограниченный этап. Проверка одного источника не означает исправность всех источников рынка.

Выполнялась только диагностическая запись под уникальными `catalog/canaries/`. Merge/deploy, переключение действующего каталога и массовый перезапуск не выполнялись. Пауза Японии сохранена.
